# 使用者更新說明

每次改變桌面功能、操作方式、修復使用者問題或調整交付套件，新增一份 `YYYY-MM-DD-topic.json`，不要重用或修改已發布的說明。

參考 [離線詞典說明](2026-11-08-offline-dictionaries.json)，填入：

- `title`：一句話說明使用者能做到什麼。
- `summary`：什麼情境下有幫助，或解決什麼困擾。
- `highlights`：一到三項具體改變；不要直接貼 commit 標題。
- `usage`：如何開始使用，以及詞典、帳號或其他必要條件。修復問題時可說明更新後適用的情境。

所有欄位都必須完成，文字欄位使用單行字串。JSON 使用 UTF-8 無 BOM。不要寫 TODO、TBD 或樣板佔位文字。格式檢查無法判斷文字是否真的有幫助，提交前仍需確認敘述符合實際功能與驗證結果。

自動發布從上一個已公開版本到本次來源 commit 收集**新增**的 JSON，讀取 Git 中的確切版本，不使用工作目錄內容。已發布的舊說明不會重複出現；若多次修改同一功能而尚未發布，可以整合於同一份新說明。首次發布則收集來源 commit 中的全部說明。

桌面或套件變更沒有新說明時，版本選擇階段即阻擋後續打包。找不到前一版 tag、歷史不完整、格式錯誤或比較範圍不是祖先時，也明確失敗。已建立 Release 的失敗重跑沿用原本內容與附件保護，不覆寫公開說明。

只有網站、文件、測試或發布工具變更時，可以不新增功能說明。發布頁會明講沒有桌面功能更新及變更範圍，告知現有使用者不需為了新功能更新。目前仍保留每次 main push 產生預覽版的節奏。

本機預覽已提交的內容：

```powershell
. ./scripts/release-notes.ps1
Get-SnapBarReleaseContent -Commit (git rev-parse HEAD) -PreviousTag v0.1.0-rc.9
```

前一版 tag 必須已在本機，可先從可信任的 remote 取得。省略 `-PreviousTag` 表示首次發布。日常 `scripts/check.ps1` 與 pre-commit 也會檢查 JSON 格式及 UTF-8 編碼。

這套流程管理 main 的自動預覽版。人工建立的正式 Release 仍由發布者撰寫說明，建議沿用相同內容與版型；附件上傳流程不覆寫人工說明。
