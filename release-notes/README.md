# 使用者更新說明

每次改變桌面功能、操作方式、修復使用者問題或調整交付套件，新增一份 `YYYY-MM-DD-topic.json`，不要重用或修改已發布的說明。

新說明參考 [雙語更新說明](2026-11-16-concise-bilingual-release-notes.json)，填入繁中欄位與相同結構的 `en` 物件：

- `title`：一句話說明使用者能做到什麼。
- `summary`：以一句話說明使用情境或改善；繁中最多 140 字元，英文最多 240 字元，不堆疊操作細節。
- `highlights`：一到三項具體改變；不要直接貼 commit 標題。
- `usage`：如何開始使用，以及詞典、帳號或其他必要條件。修復問題時可說明更新後適用的情境。

所有欄位都必須完成，文字欄位使用單行字串。JSON 使用 UTF-8 無 BOM。不要寫 TODO、TBD 或樣板佔位文字。格式檢查無法判斷文字是否真的有幫助，提交前仍需確認敘述符合實際功能與驗證結果。

英文的 `title`、`summary`、`highlights`、`usage` 必須齊全；中英文重點逐項對應、數量一致，操作名稱要與實際英文介面一致。譯文隨來源 commit 保存，由作者確認，不在發布時呼叫 AI 或翻譯服務。缺少英文會阻擋新發布。

可選欄位：

- `priority`：0–100 的整數，預設 0；較高者優先顯示在主畫面，同分依檔名排序。每種語言最多顯示三項，且兩種語言選擇相同項目；其他項目會顯示數量並保留在完整說明。
- `requirements`：必要條件 ID 陣列，可使用 `ai`、`ocr`、`python`、`node`、`dictionary`。同一版本的必要條件去除重複後，各語言統一說明一次，不在每個摘要重複 AI 金鑰或執行環境設定。
- `notice`：含 `zh` 與 `en` 的重要更新提醒。移除功能、設定遷移、資料送往外部或可能收費等會影響更新決定的資訊，必須用此欄位直接顯示，不能只放在折疊區或依賴入選前三項。

發布頁版型固定為：共用 Windows x64 下載 → 預覽版、未簽章與手動更新狀態 → 繁中最多三項摘要與一次開始使用說明 → 英文對應內容 → 預設收合的「完整說明與技術資訊」。所有功能、重點與使用方式都保留於折疊區，連同安裝、限制、來源及驗證資訊提供雙語說明。

已發布的繁中 JSON 保持原樣；既有 28 份說明的英文與必要條件等補充資料位於 [譯文對照檔](../packaging/RELEASE-NOTE-TRANSLATIONS.json)。產生說明時同樣讀取確切來源 commit 中的對照檔，不讀工作目錄，也不追溯改寫既有公開 Release。新說明應直接寫入 `en`，不要繼續擴充歷史對照檔。

自動發布從上一個已公開版本到本次來源 commit 收集**新增**的 JSON，讀取 Git 中的確切版本，不使用工作目錄內容。已發布的舊說明不會重複出現；若多次修改同一功能而尚未發布，可以整合於同一份新說明。首次發布則收集來源 commit 中的全部說明。

桌面或套件變更沒有新說明時，版本選擇階段即阻擋後續打包。找不到前一版 tag、歷史不完整、格式錯誤或比較範圍不是祖先時，也明確失敗。已建立 Release 的失敗重跑沿用原本內容與附件保護，不覆寫公開說明。

只有網站、文件、測試或發布工具變更時，可以不新增功能說明。發布頁會明講沒有桌面功能更新及變更範圍，告知現有使用者不需為了新功能更新。目前仍保留每次 main push 產生預覽版的節奏。

本機預覽已提交的內容：

```powershell
. ./scripts/release-notes.ps1
Get-SnapBarReleaseContent -Commit (git rev-parse HEAD) -PreviousTag v0.1.0-rc.9
```

前一版 tag 必須已在本機，可先從可信任的 remote 取得。省略 `-PreviousTag` 表示首次發布。日常 `scripts/check.ps1` 與 pre-commit 檢查 JSON、雙語欄位與 UTF-8；pre-commit 使用 Git index 中的說明與對照檔，工作目錄中的修正不能掩蓋已暫存的錯誤。`scripts/test-release-notes.ps1` 會產生三項 AI 更新的本機預覽 Markdown，並測試摘要上限、重要提醒、英文缺漏與完整內容保留。

這套流程管理 main 的自動預覽版。人工建立的正式 Release 仍由發布者撰寫說明，建議沿用相同內容與版型；附件上傳流程不覆寫人工說明。
