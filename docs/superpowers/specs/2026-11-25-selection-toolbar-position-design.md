# 跨欄選取的動作列定位

使用者已同意：滑鼠拖選後，動作列靠近放開的位置；跨欄優先使用附近的有效文字矩形；快捷鍵沿用文字定位，工作區邊界只負責避讓。

## 行為與取捨

不採用全部矩形的聯集，也不固定使用最後一個矩形，兩者都可能把工具列帶離注意力所在的位置。單純跟隨滑鼠雖能保持距離，卻會失去文字行的垂直避讓，因此採用附近文字行加滑鼠水平座標的方式。

Core 的 SelectionAnchor 接受螢幕實體像素矩形、輸入來源、放開座標及來源視窗 DPI 比例。拖選選擇距離放開點最近、距離不超過 48 DIP、行高不超過 48 DIP 的有效矩形，水平位置採放開點，垂直方向保留該文字行高度。沒有適合的矩形時使用放開點的 1×1 像素錨點。無效、空白或計算邊界溢位的矩形忽略。48 DIP 是保守定位門檻，不影響讀取內容或動作權限。

Probe 拖選時在已取得的選取 ranges 中挑選附近矩形；快捷鍵保留最後一個 range 的最後有效矩形。App 明確傳遞拖選來源，呈現時套用相同策略，兼顧剪貼簿來源與延遲驗證的結果。Popup 的螢幕工作區、定位和離開後自動消失邊界使用相同錨點。展開更多動作時不重新取目前游標位置。

不新增偏好、不改 Probe 契約、選取內容、密碼拒絕、前景與焦點驗證、候選身分、租期或取消流程。矩形查詢仍在隔離 Probe 內，沿用現有逾時與取消保護。此策略改善定位，不宣稱已修正瀏覽器 provider 本身。

## 實作與驗證

1. 加入 Core 定位策略，Probe 套用全部拖選矩形，App 保留輸入來源並共用錨點。
2. Core 回歸覆蓋跨欄、反向、快捷鍵、異常與過高矩形、無矩形、負座標、DPI 和螢幕邊緣；原生 Layout 檢查真實視窗座標。
3. 執行建置、相關桌面套件與更新說明檢查；在使用者開啟的 Chrome Zabbix 頁面驗證，紀錄實際觀察與限制，不記錄選取內容。

不自動提交、推送或發布套件。驗證結果記錄在 docs/p0-validation.md。
