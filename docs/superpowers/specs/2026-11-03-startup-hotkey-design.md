# 登入啟動與快捷鍵設定

日期：2026-11-03

## 目標與範圍

在既有「一般」設定頁完成登入 Windows 後自動啟動，以及更換叫出動作列的全域快捷鍵。保留既有自動偵測、系統匣、單一執行個體與選取安全檢查。本次不加入定時暫停或各動作獨立快捷鍵。

## 使用者體驗

- 新增「登入 Windows 後自動啟動」開關；新使用者預設關閉。說明文字為「登入後在背景待命」。啟用或停用立即生效，失敗時回復實際狀態並顯示可見錯誤。
- 現有快捷鍵卡片提供「更換」與「恢復預設」。更換時顯示錄製狀態，使用者按下組合後確認儲存；Esc、取消、離開一般頁或視窗失去焦點均結束錄製並放棄草稿。修飾鍵本身不構成組合。先支援 Ctrl／Alt／Shift 加英文字母、數字或 F1–F11；至少包含 Ctrl 或 Alt。按完整組合拒絕 Ctrl+C、Ctrl+V、Ctrl+X、Ctrl+A、Ctrl+Z、Ctrl+Y、Ctrl+S、Ctrl+F、Ctrl+P、Ctrl+N、Ctrl+O、Ctrl+W、Ctrl+T，以及 Alt+F4；拒絕 Win 修飾鍵、F12 與支援範圍外的主鍵。預設仍為 Ctrl + Alt + V，不得因包含 V 而誤擋。
- 錄製開始至離開編輯狀態期間，暫停執行 SnapBar 全域快捷鍵動作並清除當前選取候選；保留註冊以維持舊鍵位所有權。其他程式的快捷鍵不宣稱能完全攔截。衝突訊息為「這組快捷鍵無法使用，請換一組。原快捷鍵仍有效。」；原快捷鍵啟動時已不可用則如實說明。
- 修改快捷鍵成功後立即生效並保存；取消、無效組合、註冊失敗或保存失敗均保留原鍵位與原偏好。錯誤顯示在快捷鍵卡片並保留可繼續操作的入口。鍵位顯示、啟動狀態與錯誤訊息都使用目前設定，不再寫死預設鍵位。

## 登入啟動

Windows 層以目前使用者的 Run 登錄項目註冊完整且有引號的 SnapBar.App.exe 路徑，附加專用 `--background` 參數，不要求管理員權限。讀取與寫入僅操作 SnapBar 自己的項目；停用不影響其他應用程式。設定頁讀取實際登錄狀態，不在 settings.json 另存一份布林值。不存在項目即為關閉；指向其他位置或參數不符時不得顯示為目前版本已啟用，可由使用者明確開啟修正。

Windows 若透過啟動應用程式設定停用此項目，介面須反映停用並引導使用者到 Windows 設定恢復，不得悄悄覆寫系統停用記錄。登錄存取失敗要顯示無法讀取或變更，不能當作成功。

狀態明定為已關閉、已開啟、已由 Windows 停用及無法讀取。平時顯示開關；系統停用時開關關閉並提供「開啟 Windows 設定」入口；無法讀取時停用開關並提供重試。重新開啟設定、視窗重新取得焦點及每次變更後重讀狀態。無法辨認的系統停用資料視為無法讀取，不誤報啟用。

登入啟動的交付版本必須能脫離開發環境執行。2026-11-03 實機重開機發現開發版依賴臨時 DOTNET_ROOT，登錄存在仍因缺少全域 .NET 10 而退出。修正後以自含式完整套件交付，保留使用者已啟用的選擇並更新其啟動位置。啟用前以無副作用的 `--startup-check` 子程序清除 DOTNET／COREHOST 覆寫，從 Windows 系統目錄驗證可執行；失敗不寫登錄，顯示需使用完整套件。打包時也在此環境驗證 App 與 Probe，不能以帶入開發環境變數的測試取代此項。

只有背景啟動入口隱藏設定視窗；手動啟動仍開啟設定。背景入口須初始化 WPF 視窗 handle、輸入監聽與系統匣，但不先閃出視窗。若無法建立系統匣，顯示設定以提供退出與錯誤回饋。背景重複啟動直接返回；手動重複啟動仍喚出既有設定視窗。既有關閉到系統匣與正常退出流程維持原行為。

未啟用的使用者不會因啟動程式而被加入登入啟動。可攜式版本搬動資料夾後，舊路徑不會自行修復；使用者需從新位置重新啟用。此限制在開關說明或提示中交代。

## 快捷鍵政策與儲存

Core 定義可序列化的快捷鍵資料與有效性政策，不依賴 WPF。ApplicationSettings 升級至 schema 7，接受現有 schema 1–6 並為缺少快捷鍵的設定填入預設值，保留動作、排除 App、搜尋及相容性偏好。只有快捷鍵欄位損壞時，單獨回退預設快捷鍵，保留其他偏好，讀取時不改檔；首次明確保存前先保留原檔備份，再以正常設定保存流程修復。其他無效內容與未知 schema 沿用原檔保護機制。主畫面提示快捷鍵暫用預設值，不因此關閉既有相容性偏好。

Windows InputMonitor 接受初始快捷鍵並提供可回復的更換操作。先用另一個註冊 ID 註冊新鍵位，成功後才切換；新鍵位無法註冊時舊註冊保持有效。偏好寫入成功後才提交切換並釋放舊註冊；保存失敗時撤回新註冊。兩個註冊在準備期間都不能造成重複觸發；狀態切換由同一 UI 執行緒處理。選取控制器只轉接設定，不更動候選身分、焦點檢查、密碼欄位排除或剪貼簿安全流程。

啟動時若偏好鍵位被占用，保留使用者選擇並顯示目前鍵位不可用，允許在一般設定更換；自動偵測仍依原偏好運作，不暗中改用其他快捷鍵。

## 驗證

- Core runner：合法與非法組合、schema 1–6 遷移、schema 7 往返、其他偏好保留、無效設定原檔保護。
- Windows runner：實際註冊與切換、占用衝突後舊鍵仍可用、保存失敗回復、Dispose 清理；登錄測試使用隔離項目，不改使用者真實登入啟動偏好。
- 桌面測試：錄製／取消／恢復預設、鍵盤可操作性、衝突訊息、重啟保存、背景啟動不顯示設定、單一執行個體及系統匣失敗回退。測試須使用隔離設定與可還原的系統資源。
- 檢查一般頁正常與小視窗版面並保存截圖，執行 repository checks 與相關桌面 suites；在 docs/p0-validation.md 記錄實際結果。真實登出登入與多 DPI 未實測時明確列為未驗證，不以程序測試宣稱通過。

## 實作界線

優先新增聚焦的 Windows 登入啟動服務、Core 快捷鍵型別及一般設定控制器檔案。既有工作目錄包含 AI 設定相關未提交變更，僅在必要整合點修改，保留那些變更。正式套件發佈須另行滿足目前來源的 Release 桌面證據與既有打包規則。
