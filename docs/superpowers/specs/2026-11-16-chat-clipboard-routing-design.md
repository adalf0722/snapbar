# 聊天程式相容複製與快速路由

使用者已同意：先讓企業微信透過單次 Ctrl+C 相容讀取，再移除一般微信聊天區反覆等待 UIA 的成本。沿用已保存的相容模式偏好，不增加一般使用流程。

原生 UIA 仍優先且每次都探測。企業微信僅在已識別的主聊天視窗、有效的原生焦點與選字來源下建立讀取候選；不得把 Window 加入所有應用的通用允許清單。驗證綁定程序／視窗／焦點與候選 token，保留密碼與受保護狀態拒絕、新輸入取消、剪貼簿歸屬與完整還原。來源訊號先以實機讀取原生視窗與 MSAA 的角色／狀態確認，不讀取名稱、文字、值或剪貼簿內容到日誌。

已驗證的相容候選可提前結束無效原生重試；未知來源仍使用有界原生準備與重試。相容讀取一個手勢只送一次 Ctrl+C，不對空回應盲目再送。自動相容複製失敗後暫時退避，原生讀取與手動要求不受影響。候選資格與剪貼簿讀取授權分離於寫入授權，相容結果不能授權 Cut/Paste。

驗證包含 Core 路由／取消／退避政策、獨立桌面 fixture 的來源身分與密碼拒絕、真實企業微信和一般微信對照、剪貼簿備份還原。量測成功率和耗時；500 ms 為目標而非未驗證保證。這一輪不直接覆寫已發布套件。

方案比較：全面模仿 WinPoP 對未知視窗嘗試複製會擴大來源風險；繼續增加 UIA 重試無法處理企業微信只提供 Window 的情況。採用企業微信來源適配，並讓已驗證的備援候選直接進入複製。
