# OCR 框選體驗設計

日期：2026-11-08。使用者已同意「框選 → 辨識中 → 輕量結果卡」方向，並同意後續審查提出的減重、逾時復原與效能驗收修正，授權繼續。目前尚未完成產品實作或桌面驗收。

## 目標與範圍

一句話定義：框住文字，就能使用。

第一版交付三項改善：框內文字清晰、辨識過程有即時回應、結果可就近複製與重新框選。沿用現有 OCR 引擎、繁中／英文優先偏好與熱鍵／系統匣入口。辨識成功不自動覆寫剪貼簿。

不加入完整截圖編輯器、標註、放大鏡、選框尺寸顯示、選框微調、跨螢幕連續選框或自動偵測文字區域。搜尋直接顯示，不新增只有搜尋一個項目的「更多」選單；本次不新增翻譯入口。

## 現況與落差

- `OcrOverlay.cs` 在各螢幕顯示暗幕、左上提示、十字游標與帶藍色填色的白色選框。
- `MainWindow.Ocr.cs` 關閉遮罩後等待 100 毫秒，再呼叫 `ScreenOcr.CaptureAsync` 擷取即時桌面；辨識期間沒有狀態視窗。
- 結果目前使用 560 × 410 的可編輯視窗，提供複製、搜尋與關閉，沒有重新框選。
- `ScreenOcr.cs` 限制選區在單一螢幕內、至少 4 × 4 實體像素且不超過 16,000,000 像素。第一版保留這些選區限制。

## 互動流程

### 一、進入與框選

1. 觸發入口後取消既有文字選取工作、關閉前一張 OCR 結果卡，並隱藏會遮住擷取目標的 SnapBar 浮動介面。等待隱藏完成的桌面重繪，再擷取各螢幕快照；快照完成前不顯示框選介面。
2. 每個螢幕以自身快照作背景，疊加約 25% 黑色暗幕。不同螢幕快照不宣稱硬體同步；同一螢幕顯示和辨識必須使用同一張快照。快照只留在本機記憶體。
3. 僅在游標所在螢幕的工作區上方中央顯示固定提示：「框選要擷取的文字　Esc 取消」。游標跨螢幕移動且尚未開始拖曳時，提示跟隨切換螢幕，避免每個螢幕重複提示。
4. 保留十字游標，不新增游標旁的重複提示；單一固定提示負責說明操作。
5. 拖曳時框內顯示未加暗幕的原始快照，框外維持暗幕。選框採 1 DIP 白線搭配 1 DIP 深色外緣，不加藍色填色；提示不得遮擋選區內容，開始拖曳時隱藏固定提示。
6. 保留反向拖曳。選區限制於起始螢幕；跨出邊界時夾限，不延伸至其他螢幕。小於 4 × 4 實體像素視為未選取，繼續留在框選模式並恢復固定提示。
7. Esc 或右鍵取消整次框選、關閉所有遮罩並釋放快照。遺失滑鼠擷取時清除當次拖曳，回到待框選狀態。快照擷取失敗則清理全部資源並顯示可重試的錯誤，不以即時桌面靜默替代。

### 二、辨識中

1. 放開有效選框後，裁切已顯示的快照作為 OCR 輸入，不重新擷取桌面。清除全螢幕遮罩，立即在選區附近顯示小型狀態卡：「正在辨識文字…」，提供「取消」。
2. 狀態文字立即可見；超過 300 毫秒才顯示不定進度指示。300 毫秒是可調初值，需依量測調整，不宣稱是最佳值。完成後原地切換為結果內容，避免先關閉再彈出另一張卡；不顯示虛假的百分比。
3. 點擊取消、按 Esc 或關閉狀態卡時，立即結束 UI 工作階段。OCR 原生呼叫不保證可中途停止，但晚到結果必須丟棄，不能重開卡片或寫入剪貼簿。
4. 同時只接受一次 OCR 工作；辨識中重複熱鍵不排入新工作。取消與逾時必須結束該工作並允許重新框選，不得讓不可取消的原生辨識無限占用入口。辨識總逾時初值為 15 秒（包含工作程序啟動、傳輸及辨識），逾時顯示「辨識時間過長，請縮小範圍後重試。」與「重新框選」。此數值須依基準量測調整。
5. 實作前記錄既有引擎的實際耗時，核對原生處理是否支援可靠的中途取消。若只能在呼叫前後檢查取消，採可終止的獨立 OCR 工作程序；只終止本次工作擁有的程序，清理後才能啟動下一次工作。不能僅以丟棄 Task 結果假裝底層工作已結束。

### 三、結果與復原

1. 成功後顯示可編輯、多行、可捲動的文字區。卡片預設 420 × 300 DIP，可調整大小；最小 320 × 220 DIP，實際尺寸以所在螢幕工作區為上限，小工作區優先保留可操作性。開啟時聚焦文字區，不預選全部文字。
2. 主要操作為「複製文字」、「重新框選」與「搜尋」。存在文字選取時，複製按鈕改為「複製所選文字」；無選取則複製全部編輯內容。空白內容停用複製與搜尋。
3. 複製成功顯示「已複製 ✓」1.5 秒，再依目前選取恢復按鈕文字。1.5 秒是可調初值，檢查實際可讀性後調整。複製失敗保留文字，顯示可重試的錯誤，不顯示成功。卡片不自動消失。
4. 搜尋沿用既有網址驗證與選取文字優先規則。關閉透過卡片關閉按鈕或 Esc；不提供自動貼回來源程式的動作。
5. 沒有辨識到文字時顯示「沒有找到文字，試著只框住文字區域。」與「重新框選」。模型、執行階段及辨識錯誤維持可區別的訊息，不把缺少依賴誤報成沒有文字。
6. 「重新框選」關閉目前卡片、釋放舊快照，再重新擷取當前桌面，開始全新的框選；不得重用過時快照。

## 定位、語言與可及性

卡片以選區右下方外側為首選，間距 12 DIP；空間不足時先改放上方，再夾限至選區所在螢幕工作區。結果展開時重新計算位置，避免遮擋工作列或跑到另一個螢幕。實體像素與 DIP 轉換使用目標螢幕 DPI，支援負螢幕座標。

新增文字完整提供繁中與英文資源，遵循現有視窗開啟時的語言快照規則，不修改 OCR 原文或語言優先偏好。按鈕具備可讀取名稱、穩定 AutomationId、清楚的鍵盤焦點與 Tab 順序；狀態不能只靠顏色表達。沿用既有主題與控制項風格，狀態動畫遵守系統減少動畫偏好。

## 元件責任與資料流

- Windows OCR 模組負責擷取、持有及裁切快照，驗證實體像素選區並執行辨識。快照需具明確釋放責任，擷取失敗、取消、成功與退出皆會清理；避免讓 Core 依賴 WPF 或 System.Drawing。
- `OcrOverlay` 負責顯示快照、暗幕、提示及單螢幕選框；不直接寫入剪貼簿或啟動搜尋。
- OCR 工作協調維護單一工作階段、取消狀態、來源快照與選區身分，拒絕過期結果及過期視窗回呼。UI 狀態與原生工作占用分開管理，舊工作的 finally 不可清掉新工作。
- 狀態／結果卡負責顯示、編輯、複製、搜尋及重選事件。辨識完成後釋放影像資源，只保留必要文字與定位資訊。
- 資料流為「桌面快照 → 框選座標 → 同一快照裁切 → 本機辨識 → 結果卡」。搜尋僅在明確點擊後傳送使用者選定文字。

全螢幕快照與選區辨識使用不同的資源限制：16,000,000 像素仍是 OCR 選區上限，不可誤用成整個螢幕的上限而使 8K 螢幕無法進入。擷取或記憶體配置失敗需安全結束；實作時避免為每次滑鼠移動複製整張快照。

## 驗證與交付

- 桌面測試擷取可變動 fixture，先進入框選，再改變來源畫面，驗證 OCR 仍讀到進入時文字；驗證快照不包含 SnapBar 遮罩或結果卡。
- 驗證有效／過小／反向拖曳、Esc、右鍵、滑鼠擷取遺失、多螢幕清理、取消後晚到結果及重複熱鍵；取消不得改動剪貼簿。
- 使用可控制的停滯工作驗證逾時後工作程序已退出、入口恢復可用、下一次辨識能完成；同樣驗證手動取消及主程式退出不遺留所擁有的工作程序。
- 量測既有與新版的熱鍵到可框選、放開到首次回應、辨識完成時間及記憶體峰值。各做一次冷啟動及五次暖啟動，記錄螢幕解析度、DPI、選區像素、耗時範圍與記憶體用量。量測不記錄畫面或文字，只用可丟棄 fixture；沒有對應硬體時明確標記 4K／8K 未量測。
- 驗證辨識中狀態、空結果、依賴缺少、複製成功／失敗、選取文字複製、編輯後搜尋、重新框選取得新畫面與結果卡邊界定位。
- 執行 repository `scripts/check.ps1`，並依 `scripts/test-desktop.ps1 -List` 選取 OCR、介面語言與外觀相關桌面套件；保留現有繁中／英文辨識測試。測試開始前需正常結束既有 SnapBar。
- 保存框選、辨識中、成功及空結果截圖；驗證標準與受限工作區，人工檢查可用的 100%／150% DPI 與混合 DPI／多螢幕環境。未具備環境者明確列為未驗證，不以單螢幕測試推論通過。
- 實作完成新增唯一命名的繁中 `release-notes/*.json`，在 `docs/p0-validation.md` 記錄實際證據與限制。本規格提交不代表產品功能已完成，不進行發布或替換既有套件。

## 規格自查

已核對：選框與 OCR 共用快照、狀態卡不進入 OCR 影像、取消後結果不回流、重選取得新快照、單螢幕邊界與 DPI 轉換規則一致。首版不擴大動作權限、不記錄選取文字、剪貼簿或畫面內容，不變更既有一般選字安全政策。
