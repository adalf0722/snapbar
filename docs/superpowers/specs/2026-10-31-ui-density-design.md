# SnapBar UI 密度與測試結果精修

日期：2026-10-31。使用者已同意前一輪截圖評估的三項精修，授權繼續。

## 已確認方向

沿用現有灰白與藍色視覺。設定頁收合列縮至約 48 DIP，動作管理的預覽區高度縮短約三分之一、清單列縮至 56 DIP。可操作按鈕保留正常對比，僅真正停用時淡化；腳本新建時預設終端機圖示，保留已儲存及使用者明確選擇的圖示。

## 設定與回饋

搜尋及診斷使用較小的卡片內距，展開才占用額外高度。正常選取紀錄、字數、剪貼簿狀態與耗時僅出現在診斷內；設定保存失敗、驗證失敗及初始化問題仍在主畫面提供可見回饋，不能因診斷收合而消失。快捷鍵衝突與初始化失敗也反映在頂部運作狀態。

## 動作管理

預覽仍呈現真實工具列高度與六個完整釘選項目；只縮短外圍空間。位置選單與上下排序仍可使用。減少卡片間距，不新增導航系統或重做配色。

## 編輯及測試

提高執行測試按鈕對比，儲存維持主要藍色按鈕。待測試使用較小的結果空狀態；成功後呈現原始唯讀輸出、輸入與輸出字數及是否相同。提供可展開的空白／換行比較，符號僅出現在比較區，不改變腳本、輸入及原始結果；空格用 ·、Tab 用 ⇥、CR 用 ␍、LF 用 ↵ 並保留實際換行。

測試開始時擷取範例及編輯版本；執行中修改內容後，舊結果不得誤標為新範例的結果。失敗仍使用既有完整診斷；取消、儲存不執行、焦點與來源選取安全規則均保留。

## 驗證

沿用既有 Core 及相關 Windows console runners。擴充 UI appearance runner，驗證比較區原始文字保存、編輯失效、空白可視化及圖示預設；輸出新截圖至 artifacts/ui-polish。檢視一般與最小視窗。發布前安全退出目前舊版本，保留使用者設定；不自動儲存開啟中的動作編輯器。

## 使用者確認後的收斂修正

使用者再次檢視實際截圖後，已授權省略空的「隱藏」群組，並在展開進階設定時將第一個欄位（含標籤）捲入視野。使用 layout 完成後的 BringIntoView，只改捲動位置，不移動鍵盤焦點；收合後排入佇列的操作不得再次捲動。浮動工具列改做實際選字、定位、滑鼠回饋及消失時機驗收，不另行改造風格。
