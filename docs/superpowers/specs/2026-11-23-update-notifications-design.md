# 更新通知設計

日期：2026-11-23

狀態：已同意產品方向；本文件供實作前檢閱。

## 目標與範圍

讓使用者知道有值得安裝的 SnapBar 新版本、理解更新的好處，並能找到該版本的下載頁。通知在背景檢查後出現，不搶焦點，同一版本最多主動提醒一次。

第一版提供背景檢查、系統匣輕提醒、持續可見的更新入口、手動檢查，以及關閉自動檢查的偏好。下載與安裝仍由使用者進行；不下載執行檔、不替換現有套件、不結束 SnapBar，也不修改登入啟動位置。

## 已確認的現況

- `ProductVersion` 已識別 Stable、Preview、Development、Test，但尚無版本先後比較。
- `TrayIcon` 已使用 WinForms NotifyIcon；左鍵開設定，右鍵有操作選單，關閉設定視窗時也會發出提示。
- `SettingsSupportPage` 已顯示公開版本及通道，可加入更新區塊。
- 每次 main push 可發布預覽版，部分發布只有網站、文件或工具變更，不應因此主動提醒桌面使用者。
- 發布工具從確切來源 commit 及前一公開版本彙整雙語更新說明，現有 ZIP 與 SHA-256 完整性檢查必須保留。
- 套件使用者目前需要完整結束舊版、完整解壓縮新套件再啟動。使用者設定保存在 LocalAppData。

## 方案選擇

採用 GitHub Releases API 加上發布時產生的結構化摘要。好處是沿用既有發布來源、可涵蓋預覽版、公開後不需等待官網部署。代價是需要處理匿名 API 限流及分頁。

另兩個方案：官網靜態 JSON 可減少 API 使用，但通知會依賴網站部署成功；僅提供手動檢查最簡單，但無法滿足常駐使用者主動感知更新的目標。第一版採上述 GitHub 方案。

## 使用者體驗

### 背景檢查與通知

1. 公開版本首次啟動後等待 30 秒，再於背景檢查；後續依本機記錄的最後嘗試時間，每 24 小時最多一次。重開程式不重置間隔。
2. 自動檢查預設開啟。「關於與支援」提供「自動檢查更新」開關及文字，說明會連線 GitHub 取得公開版本資訊，可隨時關閉。開關持久保存，關閉後取消排程與進行中的背景請求，但保留手動檢查。
3. 取得合適新版後，更新設定頁與系統匣右鍵的持續入口。當尚未提醒過該版本，且 SnapBar 沒有進行選取探測、剪貼簿操作、自動複製等待、動作執行、顯示動作列、AI 作業或 OCR 流程時，才發出一次系統匣通知。
4. 操作忙碌時只保留一份待提醒結果；由操作狀態改變或每 5 秒重新檢查時機，不取消選取、不呼叫探測、不讀取文字或剪貼簿。持續忙碌便延後，離開程式時不強行顯示。
5. 通知標題為「SnapBar 有新版本」，內容包含版本與最高優先的一句更新摘要；通道以本地化文字標示。摘要以純文字顯示並限制長度，完整內容可在更新區塊及發布頁查看。
6. 通知點擊後，開啟設定的更新區塊；再由「查看更新與下載」開啟已驗證的該版本發布頁。既有「已縮到系統匣」提示仍開一般設定，不共用可能過期的點擊目標。
7. 每一目標版本在送交系統匣通知前先原子保存已提醒狀態；保存失敗時本次執行記憶去重，取消主動通知，持續入口仍可使用。Windows 抑制通知或程式意外結束可能使提示未出現，入口仍存在，不因此重複打擾。

### 持續入口與手動檢查

「關於與支援」在版本資訊下方提供更新區塊，包含目前狀態、「檢查更新」、自動檢查開關。找到新版時顯示版本、最多三項摘要、必要提醒及「查看更新與下載」。系統匣右鍵出現「有新版本…」入口並導向同一區塊，不改變既有圖示的自動／手動模式含義。

狀態包含：尚未檢查、檢查中、目前已是最新版本、有新版本、暫時無法檢查、開發／測試版本不提供更新。手動檢查不另發主動通知；發現新版便直接更新此區塊。

手動檢查可略過 24 小時間隔，但同時只允許一個請求，且至少間隔 60 秒。遇限流需遵守伺服器提供的重試時間，按鈕顯示可再次檢查的時間。背景與手動檢查共用同一請求及結果，避免並行競態。

下載按鈕附近明確顯示：「請先從系統匣結束舊版，再完整解壓縮並開啟新版。原有設定會保留。」網頁只在使用者點擊下載按鈕時開啟。

## 版本與通道規則

- 正式版只接受更高的正式版。預覽版接受更高的預覽版或正式版；例如 `0.1.0-rc.9 < 0.1.0-rc.10 < 0.1.0 < 0.1.1-rc.1`，正式版使用者不會收到最後一項預覽版。
- 依 SemVer 比較數字及預發布識別，不使用字串排序或發布時間決定升級，不因重新發布舊版而降級。來源 SHA 不影響版本先後。
- Development、Test 或無法解析的本機版本不自動連網、不提示升級；測試使用注入的公開版本。
- 僅接受非草稿、合法公開版本、prerelease 旗標與通道一致，且對應 win-x64 ZIP 與 `.sha256` 均完整上傳的 Release。重複版本資料或矛盾識別視為來源錯誤，不猜測。
- 檢查完整掃描結果中符合通道的最高版本，維持現有「新版可下載」入口；只有包含桌面／套件變更且有有效結構化摘要的版本可主動通知。純文件版本不遮蔽掃描結果中尚未提醒的較早桌面版本。
- 若入口顯示的最新套件與主動通知目標不同，兩者各自保存版本與摘要；通知點擊先顯示通知所指版本，下載頁與摘要必須一致。
- 未帶本機可解析摘要的舊 Release 可作為下載入口候選，使用固定「查看此版本的完整更新說明」文案；不能解析 Markdown 猜測收益或是否值得主動提醒。

## 發布資料契約

在新建立的 Release body 加入唯一標記 `snapbar-update-v1` 的 HTML 註解，內容為 UTF-8 JSON 的 Base64，避免與既有 Markdown、註解結尾及模板混淆。契約版本為 1，包含：

- `schemaVersion`、`version`、`sourceCommit`。
- `desktopChanged`：依既有桌面／套件路徑政策判定真實變更；不得僅以「存在 release note」推定。
- `zh`、`en`：各包含最多三筆 `summaries` 與必要 `notices`，沿用現有優先順序及重要提醒不隱藏的規則。

摘要由既有更新說明物件產生，與人類可讀的 Release body 共用來源，不能從格式化 Markdown 反向解析。單筆摘要沿用繁中 140 字元、英文 240 字元上限；必要提醒最多 2,000 字元，整個解碼後契約最多 32 KiB。超限、缺少翻譯、非法控制字元或重複標記，在新發布前失敗。

桌面端驗證契約版本、版本與 Release tag 一致、SHA 格式、資料型別及字串上限。未知契約或無效契約只能作為無摘要候選，不能觸發主動通知。遠端內容只呈現純文字，不載入 HTML、影像、腳本或內容中的網址。

自動預覽發布與人工正式版入口都在公開前驗證新版本契約。延續現有不可覆寫政策：同 run 重跑沿用原 body；既有公開 Release 與歷史說明不回填、不重寫。功能上線前已存在且沒有契約的草稿可完成既有發布，但不得被桌面端主動通知；新草稿必須有契約。

## 網路、排程與錯誤處理

- 只查固定 `adalf0722/snapbar` 的公開 Releases，不帶 token、使用者識別、選取文字、剪貼簿或設定檔內容。GitHub 仍會收到一般連線資訊與來源 IP。
- 使用公開的 list releases API，不以 latest endpoint 代替通道選擇。每頁最多 100 筆，依分頁連結循序讀取，最多 10 頁；總請求期限 30 秒，每頁內容最多 8 MiB。到達上限但仍有下一頁時，顯示暫時無法確認，不宣稱已是最新，也不使用部分結果發新通知。
- 僅接受固定 GitHub API 來源的後續分頁 URL；停用自動跨主機重新導向。外開發布頁由已驗證版本自行組成固定 repository 的 HTTPS URL，不直接信任回傳網址。
- 當網路失敗、逾時、資料損壞或被限流，背景檢查安靜結束，手動檢查顯示可理解的狀態。限流採 Retry-After 或 reset 時間及最少一小時退避；背景仍維持至少 24 小時間隔，不立即重試。
- 查詢失敗時保留最後有效的可用版本並註明上次檢查時間；不把舊結果說成剛確認的最新結果。完整成功檢查若發現版本撤回或附件不完整，移除該候選及待通知；已提醒紀錄保留。
- 結束、關閉自動檢查或新一代請求取代舊請求時取消工作；完成後必須重驗執行世代及生命週期，禁止已退出後通知、寫入結果或啟動瀏覽器。

## 本機保存與模組責任

獨立保存 `%LOCALAPPDATA%/SnapBar/updates.json`，避免背景更新排程覆寫使用者一般設定。包含 schema 1、自動檢查偏好、最後嘗試與成功時間、退避時間、最多 64 筆已提醒版本、最近有效候選及取得時間。總大小限制 64 KiB，原子寫入 UTF-8，保存時序列化以避免手動／背景互相覆蓋。

無檔案使用預設。損壞、較新 schema 或無權寫入時保留原檔，不啟用背景檢查或主動通知，設定頁提示狀態但手動檢查可用。已提醒紀錄達上限時保留語意版本最高的 64 筆；舊版不會變成升級候選。

- Core：公開版本比較、候選篩選、摘要契約驗證、通道與去重政策、本機狀態保存。不依賴 WPF 或原生選取流程。
- Windows：固定來源的 HTTP 查詢、限流與取消處理，接受可注入 HTTP handler 與時鐘。
- App：更新協調器、生命週期、忙碌狀態快照、系統匣與設定 UI、語言刷新。忙碌快照只暴露布林狀態，不能藉此放寬操作權限。
- 發布腳本：產生及驗證契約，保持既有 ZIP／SHA-256 核對與不可覆寫限制。Probe 不新增更新工作。

## 驗證與交付

1. Core runner 驗證正式／預覽通道、rc 數值排序、正式版轉換、未知版本、重複候選、只有文件更新、跨多個未安裝版本、契約缺漏與不合法內容、狀態保存與既有偏好互不覆蓋。
2. HTTP fixture 驗證分頁、100 筆以上、頁數／大小／期限上限、錯誤回應、限流、惡意分頁／外開 URL、取消與晚到結果。測試不呼叫真實 GitHub。
3. 桌面 runner 以注入來源驗證不搶焦點、忙碌時延後、同版本跨重啟去重、持續入口、舊系統匣提示點擊不誤開更新、語言切換、關閉檢查、手動檢查與結束取消。納入 Release 必要證據。
4. 發布工具驗證兩種語言與契約一致、純文件變更不主動提醒、正式／預覽入口、新草稿契約、同 run 重跑不改公開內容，及原有雙附件完整性檢查。
5. 實作時新增唯一命名的繁中／英文 release note，更新開發文件及套件使用說明，並記錄桌面截圖與實測。交付前執行 repository checks 及適用桌面套件；發布仍遵守完整 Release 證據要求。

## 外部依據

- [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#list-releases)：公開 Release 可匿名取得，list 包含公開預覽版，每頁上限 100。
- [GitHub REST API rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)：匿名請求以來源 IP 計算，需處理共用網路下的限流。
