# 更新檢查排程調整

使用者已同意：保留啟動後 30 秒等待；預覽版每小時、正式版每天檢查；手動檢查取消 60 秒冷卻，仍共用進行中的請求並遵守 GitHub 限流。

採用依最後成功時間排程，避免失敗後等待一整天。一般失敗依序等待 5、10、20、40、60 分鐘，後續維持 60 分鐘；成功即清除失敗計數。自動重試時間與失敗計數保存至更新狀態，重開後沿用。舊狀態缺少新欄位時使用預設值，保留既有偏好與通知去重資料。

一般失敗只限制背景重試，手動仍可立即重試。GitHub 限流同時限制背景與手動請求，沿用既有可再次檢查時間提示。保持版本篩選、手動結果不另跳通知、同版本去重、忙碌延後及取消過期請求的行為。

驗證涵蓋通道週期、啟動等待、重開持久化、失敗退避與成功重置、手動立即重試、共用進行中請求、限流及既有通知回歸。無介面版面變更，不發布套件。
