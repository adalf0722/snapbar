# SnapBar 設定導覽與對外介面設計

日期：2026-11-01。

狀態：使用者已核准 A「左側固定導覽」與受限工作區、草稿生命週期、AI 命令排序及刪除復原修訂，並授權實作。實作與本機回歸已完成；實際測試證據及實體混合 DPI 驗證限制記錄於 `docs/p0-validation.md`。

## 目標與現況

目前 `MainWindow` 將全部設定放在單一 `StackPanel` 與整頁 `ScrollViewer`，預設視窗就會出現垂直捲軸。動作管理及 AI 服務另開視窗，AI 命令新增、編輯、刪除只存在 AI 執行面板。設定分類與管理入口尚未形成完整體驗。

採用 A 草圖的左側導覽與右側內容區。一般設定在預設尺寸內完整可見，AI 命令可直接從設定管理，不需要先選取文字或建立執行工作階段。整合既有功能並統一視覺，不新增網站、帳號、付費、同步或真實 AI 測試請求。

參考草圖位於本機 `.superpowers/brainstorm/settings-20261101/content/settings-layout.html`。該目錄被 Git 忽略，正式需求以本文件為準；瀏覽器草圖的 S 字母標誌、模擬資料及未接通的按鈕不直接成為正式產品資產或功能。

## 導覽與頁面

左側導覽固定顯示六個分類，單層結構，圖示搭配文字。右側固定頁首、內容區與頁尾。切換分類不保存任何使用者偏好，也不重新載入或重設草稿。預設開啟「一般」，同一次程序內重新開啟設定保留目前分類。

| 分類 | 內容與主要操作 |
| --- | --- |
| 一般 | 自動偵測開關、既有 Ctrl+Alt+V 快捷鍵說明、動作列示意與前往動作列設定入口、關閉後背景待命說明 |
| 動作列 | 既有動作預覽、外觀、動作列／更多／隱藏分組、排序、新增、編輯、匯入、刪除及復原；搜尋引擎設定作為同頁的次級「搜尋」子頁 |
| AI 命令 | 命令搜尋、分類篩選、穩定排序的命令清單、釘選、新增、編輯、刪除及復原；可直接開啟既有圖示選擇器，服務未設定時提供設定入口 |
| AI 服務 | 既有服務選擇、完整 API 網址、模型 ID、API Key、既存金鑰狀態與移除金鑰選項；明確儲存服務設定 |
| 相容性 | 選字相容模式、Sublime 支援、排除 App 清單與加入／移除操作 |
| 關於與支援 | 真實版本資訊、背景待命說明、結束 SnapBar；進階區保留診斷事件與測試視窗入口 |

動作列頁的「動作／搜尋」次級導覽保持可見；既有動作位置分組在「動作」子頁內運作。搜尋保留 Google、Bing、自訂選擇，以及明確儲存和恢復預設；切換子頁不得丟失未保存的自訂網址。

關於與支援頁不放置尚不存在的說明、回饋或更新連結。現有可用功能先形成完整頁面，日後有真實支援網址才新增連結。

## 尺寸、捲動與視覺

- 初始目標尺寸為 980 × 720 WPF DIP，標準配置的最小目標為 860 × 600 DIP，兩者均以實際工作區容納得下為前提。工作區限制優先於目標尺寸與 `MinWidth`／`MinHeight`；工作區不足時必須降低有效最小尺寸，不能因 WPF 最小尺寸限制而將視窗或操作按鈕擠出螢幕。
- 開啟及跨螢幕移動時依目前螢幕的 DPI 和工作區重新限制視窗尺寸與位置，包含標題列及視窗邊框，排除工作列。不得以固定像素假設取代 WPF DPI 換算。例如 1366 × 768 像素螢幕在 150% 縮放下，完整螢幕高度僅 512 DIP，實際工作區更小，不能再強制要求 600 DIP 視窗高度。
- 導覽欄約 180 DIP；頁首與頁尾使用自動高度，中間內容使用剩餘空間。標準配置頁面外距以 24–32 DIP 為主，資料列間距與控件高度遵循現有樣式。
- 設定視窗根節點不使用整頁垂直 `ScrollViewer`。一般頁在標準配置內不得出現垂直捲軸，也不得裁掉內容。
- 命令、動作、排除 App 與診斷事件數量可增加，只允許各自有界的清單區捲動。導覽、主要操作、通知與頁尾保持可見。
- 工作區不足以容納標準配置或文字放大導致可用空間不足時，依序縮減外距與裝飾性留白、收起一般頁的動作列預覽及長篇輔助說明，並將並排表單欄位改為單欄。導覽文字、一般頁的自動偵測開關與快捷鍵、主要操作、未儲存狀態及錯誤提示仍需保留。預覽可從動作列頁查看；被收起的長篇說明提供可展開入口，剪貼簿副作用等必要說明不得省略。
- 上述調整後仍無法容納的密集內容，允許右側內容區局部捲動，一般頁在受限配置下也適用此例外；固定導覽、頁首及主要操作不隨內容捲走。不得直接隱藏捲軸而使內容無法到達，也不得把所有文字或控件整體縮小。此規則優先於標準配置的一屏要求。
- 服務與命令編輯的多行輸入可局部捲動；現有彈出編輯器仍需完整可操作。
- 保留現有淺灰背景、白色內容面、低對比邊線與單一藍色重點色。減少重複卡片和大標題；頁面標題約 22–24 DIP、主要文字 13–14 DIP、輔助文字至少 12 DIP。
- 使用既有 Fluent 圖示與產品品牌資產，圖示尺寸及筆畫一致。一般頁預覽反映使用者的實際動作排列、主題與標籤偏好，並說明正式顯示依選取情境決定；預覽不執行動作。
- 自動偵測狀態使用文字加圖示表達，不能只靠顏色。保留快捷鍵衝突、初始化失敗和設定保存失敗的明確提示。

## AI 命令管理

清單使用目前 `AiSettings.Prompts`，不建立第二份命令資料或新 schema。每列顯示現有圖示、名稱、分類及釘選狀態，提供明確的編輯入口與可存取的次要選單。

管理清單固定依 `Prompts` 的儲存順序顯示；新增命令附加在末尾，編輯與釘選不改變其位置。搜尋與分類只篩選這份順序，不以最近使用時間、名稱或釘選狀態重新排序；清除篩選後回到原順序。AI 執行面板維持既有釘選與最近使用排序，不直接將該排序套用到管理清單。

搜尋比對名稱、指示與關鍵字；搜尋與分類篩選同時生效。分類來自現有命令，包含「全部分類」與未分類項目，不能只支援草圖中的三個固定分類。空集合、無搜尋結果與達到既有 128 筆上限時都顯示對應狀態。保留全部既有名稱、指示、分類、關鍵字及圖示上限。

新增與編輯重用 `AiPromptEditorWindow` 的驗證、圖示預覽、進階選項與圖示選擇器。編輯維持原命令 ID；取消不保存。釘選更新 `PinnedIds`；刪除透過既有正規化移除失效的釘選與最近使用參照，不修改其他命令。

刪除成功後在固定操作區顯示「已刪除『命令名稱』〔復原〕」，不另加每次刪除的確認對話框。設定管理與 AI 面板透過共用的命令管理邏輯提供相同的刪除及復原能力；同一程序只保留最近一次成功刪除的紀錄，兩處同步顯示其狀態。切頁、篩選、其他命令變更或收至系統匣不會清除紀錄；復原成功、下一次成功刪除或程序結束才失效，不新增跨次啟動的回收站。

復原只記錄被刪除的命令、原 `Prompts` 索引及原釘選位置，將命令合併回最新集合，索引超過目前長度時放至末尾；不以舊設定快照覆寫其他命令、服務、釘選或最近使用的變更。原本已釘選者回到目前釘選集合的原索引範圍內，未釘選者維持未釘選；不恢復已移除的最近使用紀錄。已有相同 ID 或目前已達 128 筆時拒絕復原並保留提示。刪除保存失敗時維持目前集合及原復原紀錄；復原保存失敗時維持刪除狀態與復原入口，皆顯示錯誤。復原成功但命令不符合目前篩選時，提示「已復原；目前篩選未顯示」，不擅自清除篩選。

設定管理與 AI 面板共用 `AiPreferences`。保存成功後兩處即時刷新；仍在編輯的命令草稿不因其他命令變動而被覆寫，提交時以最新集合套用當前命令變更。保存失敗保留草稿並顯示錯誤，不顯示成功或清空編輯內容。

目前服務的網址或模型未完成有效設定，或依既有執行規則需要金鑰但目前網址尚無金鑰時，命令頁顯示「尚未完成 AI 服務設定」與「設定 AI 服務」入口，切換至對應分類，不阻擋新增、編輯、分類、釘選、刪除與復原。此狀態只依本機設定與既存金鑰判斷；允許不填金鑰的本機相容服務不因此被判定為未設定，未發送請求前不宣稱服務已連線或金鑰有效。

AI 面板保留既有快速新增、編輯與釘選能力，並提供前往設定中 AI 命令分類的入口。設定頁不提供「執行命令」按鈕，不建立無來源選取的寫回路徑。

## 元件與資料流

`MainWindow` 維持程序生命週期、系統匣、控制器及設定保存的協調角色，負責目前分類與全域狀態，不繼續累積六頁的完整建構程式。

將各頁整理成職責明確的 WPF 內容元件。動作管理與 AI 服務的既有視窗改為共享內容的宿主，以便設定頁嵌入；既有呼叫端與桌面測試需要獨立視窗時仍能使用同一份內容，不複製保存邏輯。

動作設定仍走既有正規化、保存回呼與 `SelectionController.ConfigureActions`。AI 設定仍透過 `AiPreferences.TrySave`、`Changed` 與 `AiSecretStore`；已保存服務與金鑰的保留、清除及錯誤語意不變。

從控制器或其他視窗要求「管理動作」時，顯示並啟用設定視窗，切至動作列頁；要求管理 AI 命令或服務時切到對應頁。不得同時建立不同步的兩個管理實例。設定切頁不終止執行中的 AI 請求，也不改變既有來源失效與取消規則。

既有自動偵測、相容性、動作排序與釘選仍在明確操作後依原契約立即保存。AI 服務、搜尋與命令編輯採明確提交，狀態與退出規則如下，不以切頁或關閉到系統匣當作保存動作。

### 未儲存狀態與草稿生命週期

AI 服務與搜尋頁在目前有效設定和草稿有差異時顯示「尚未儲存」，頁內固定操作區提供「儲存」與「捨棄變更」。服務下拉選擇也屬於服務草稿，提交前不改變實際使用的服務。修改後還原至有效值即清除未儲存狀態；輸入新金鑰或勾選移除既存金鑰也會使頁面成為未儲存狀態。

命令編輯器保留既有儲存與取消按鈕，修改後顯示「尚未儲存」。取消或關閉編輯器即捨棄該次命令草稿，不影響已提交的其他命令；命令管理清單本身沒有整頁待提交的副本。未完成命令編輯前，不另外開啟同一命令的第二個編輯器。

| 操作 | 草稿與保存行為 |
| --- | --- |
| 切換分類或搜尋子頁 | 保留目前服務與搜尋草稿，不保存、不彈出離頁確認；返回原頁可繼續編輯 |
| 關閉設定視窗到系統匣 | 保留同一程序內的服務與搜尋草稿；重開保留目前分類與未儲存狀態，不自行保存 |
| 儲存 | 驗證並保存目前表單；成功後更新基準值、清除該表單的未儲存狀態並顯示「已儲存」，設定頁留在原處；獨立編輯宿主可依原契約關閉 |
| 捨棄變更 | 將目前頁的草稿重設為最新有效設定，包含該頁各服務的未提交欄位、金鑰輸入與移除金鑰選項；不刪除已保存的金鑰，不撤銷已生效的其他操作 |
| 真正結束程序 | 有未提交草稿時只顯示一次「儲存後結束／捨棄並結束／取消」選擇，適用設定頁與系統匣的結束入口，並納入尚開啟的命令或服務編輯器草稿；沒有草稿則沿用原結束流程 |

「儲存後結束」逐項透過既有驗證與保存入口提交未儲存表單；任一項驗證或保存失敗即取消退出、顯示並定位失敗表單，保留其未提交內容。已成功的表單不回復為未儲存，也不宣稱這是跨檔案交易。對話框必須明示將儲存的表單；有未提交的金鑰時包含金鑰變更。「捨棄並結束」清除草稿後沿用正常退出流程，「取消」保持程序及草稿不變。系統強制終止或崩潰不保證草稿恢復，也不新增草稿落地保存。

未提交金鑰只暫存在本程序的表單及既有服務草稿中，不額外寫入一般設定、草稿檔案或日誌。切頁與隱藏視窗不清除待提交金鑰；保存金鑰成功、捨棄對應服務頁變更、取消獨立服務編輯器或真正退出時清除其輸入控件與待提交參照。既存金鑰維持既有保護與存取規則，不將其內容回填到草稿或畫面。

驗證失敗或保存失敗時，不清空草稿、移除錯誤或顯示完整成功。服務欄位已保存但金鑰保存失敗時，明確顯示「服務設定已保存，但金鑰無法保存」，保留未完成的金鑰變更供重試；只有全部待提交變更完成才清除該頁的未儲存狀態。執行中的 AI 請求仍依既有服務變更與取消規則處理。

各頁的驗證錯誤顯示在對應欄位或固定操作區；全域初始化、熱鍵及設定保存錯誤顯示在固定通知區。重要錯誤不得因切換分類而消失或被成功訊息掩蓋。頁尾避免宣稱所有內容皆已自動保存。

## 安全、相容與可存取性

保留密碼欄位拒絕、前景／焦點／候選身分驗證、過期結果取消、剪貼簿讀寫限制及原文替換權限。設定重整不得更改 Core、Windows 或 Probe 的動作許可政策。

一般剪貼簿相容模式遵循既有預設及保存偏好；Sublime 初次設定沿用明確啟用流程。保留暫借剪貼簿及可能出現在剪貼簿歷程的說明，不以視覺精簡移除實際副作用資訊。

API Key 不顯示為明文、不寫入一般設定或日誌；保留現有服務及網址分開保護的規則。診斷與新增 UI 日誌不得包含選取文字、命令輸入、AI 回應或剪貼簿內容。

導覽與清單提供文字標籤、焦點樣式及穩定的 Automation ID。Tab 可遍歷全部操作；導覽支援方向鍵與 Enter／Space 切頁。切頁後焦點留在可預期的導覽項或目標頁，不遺留於已隱藏的控件。命令篩選與刷新後保留可用焦點；IME 組字不得被導覽快捷鍵中斷。

## 驗證與完成條件

1. 檢查六個分類與外部管理入口，確認設定視窗可重開、系統匣與結束操作維持原行為，切頁與隱藏不重置保存值、草稿或未儲存標記。驗證捨棄只影響目前頁，退出時儲存、捨棄、取消與失敗停止退出的行為；無草稿時不得新增確認。
2. 在 100%、125%、150% 顯示縮放、初始尺寸、標準配置最小尺寸及受限工作區檢視實際 WPF 截圖，至少包含 1366 × 768 像素與 150% 縮放，以及跨不同 DPI 螢幕移動。一般頁在標準配置無垂直捲軸，受限配置依序縮減留白與收起預覽後才使用內容區捲動；視窗含邊框不超出工作區，每頁標題、主要操作、未儲存狀態與錯誤提示可達。
3. 桌面案例驗證無選取即可管理 AI 命令、新增／編輯／取消／刪除／釘選、搜尋加分類、圖示、命令上限、失敗草稿保留，以及管理頁與既有 AI 面板同步。驗證最近使用與釘選變更不移動管理清單、新增位於末尾、篩選保留順序；未設定服務仍可管理命令，入口可正確切到 AI 服務，允許無金鑰的本機服務不出現錯誤設定提示。
