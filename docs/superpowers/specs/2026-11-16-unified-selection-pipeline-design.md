# 統一 UIA 與 Ctrl+C fallback

使用者同意採用 UIA 快速讀取與共用 Ctrl+C fallback，並明確要求擴大尚未辨識 App 的相容讀取。

Core 協調器統一原生探測、候選資格、讀取執行、過期取消及自動退避。UIA 成功直接返回，不解析或呼叫 fallback；no-selection、password、逾時和焦點失效等終止狀態不轉成複製權限。原生及備援結果必須屬於原始目標。

未知 App 可使用通用原生來源驗證，不要求 App 名單：原生焦點和滑鼠位置必須同一控制項並屬於目標程序／根視窗；MSAA 須正向提供文字／文件角色及目前焦點狀態，不得有保護、停用或隱藏旗標。缺少這些證據的未知 opaque Window 不直接複製。企業微信保留已驗證的 opaque 適配；Sublime 保留需明確設定的條件快捷鍵。這些只提供候選及讀取計畫，不另寫協調流程。

沿用相容模式偏好、終端機排除、完整剪貼簿備份還原、單次複製與讀寫權限分離。測試涵蓋原生成功零複製、所有終止狀態零複製、未知 App 正向來源、未知／密碼／異程序來源拒絕、原生焦點變更及取消、手動不受退避影響，並以真實原生 EDIT／password／BUTTON fixture 驗證 MSAA 訊號。

方案比較：全面對未知 Window 發 Ctrl+C 會失去來源與保護判斷；維持所有 App 個別分支無法擴充。採用一個協調器、依來源能力選擇候選，保留少數必要適配。前述方向已獲使用者授權，不另增加操作開關。
