# 剪貼簿回退與 Sublime 寫入

本次依 `docs/2026-10-23-clipboard-fallback-handoff.md` 已確認方向續作。範圍是 Windows 的最小共用邊界與 Sublime 剪下／貼上；Electron 與 macOS 留待各自實測，不增加未驗證的適配器。

## 路由與元件

原生 UIA 優先。helper 必須區分沒有 TextPattern 的「不支援」與有 TextPattern 但沒有選取；只有不支援且目前目標符合已驗證 Sublime 策略、使用者已啟用相容模式時，才啟動回退。密碼、逾時、失效與確定無選取均停止。

剪貼簿協調器負責串行、完整備份、序號／目標／輸入檢查、讀取與還原，不含 Sublime 設定或鍵位。Sublime 適配器負責辨識目標、驗證設定、產生條件複製步驟與動作指令。

## 可編輯能力

考慮過只解除按鈕限制、所有讀取都要求可編輯，以及分開確認讀取／寫入能力。採第三種，以保留唯讀選取的複製能力，又不把未知狀態當作可編輯。

每次手勢最多一個協調器交易，僅第一個有回應的條件複製會成功。先送 F11：單段、非空、非面板／覆蓋介面且 `read_only not_equal true` 才 copy。收到新內容才產生 `Editable=true`。無回應時，可於同一備份交易送既有 F12 讀取；這條路徑保持 `Editable=null`。唯讀／空選取需多等一個等待窗口；不快取可編輯結果。Build 4180 實測 `equal false` 落到 noop，而明確 `not_equal true` 才正常；不能僅憑文件推論兩種寫法在該版等效。

動作前重新以 F11 驗證；複製可以使用一般讀取。剪下 F10／貼上 F9 均有 noop 預設及同樣的選取／可編輯條件，絕不退回 Ctrl+X／Ctrl+V。送出指令只回報已送出，不宣稱文件已修改。

## 剪貼簿與競態

貼上記住點擊時的剪貼簿序號；重新讀取須保存並還原該份完整內容，還原後立刻記住新序號。執行前若序號不同就取消。剪下指令送出後不再還原探測備份。任何備份失敗均在注入前停止。已辨識的並行寫入保留其內容。

使用者鍵盤／滑鼠輸入使快照失效；動作前比對文字、程序啟動身分、前景、修飾鍵與代次。Sublime 無外掛介面無法提供範圍位置，因此相同文字被背景程式移到另一個範圍仍無法辨識；無擁有者寫入、晚到事件、檢查到注入間競態也非原子交易。寫入條件在 Sublime 執行當下再次檢查，降低風險，但不保證排除所有外部自動化競態。

## 設定升級與撤回

保留原 F12 兩條綁定，新增 F11、F10、F9 各一組 noop／條件指令。僅識別完整符合舊版的綁定才升級；被修改、重複或新增鍵位衝突一律拒絕。插入時保留既有文字、註解、順序與尾逗號，寫入前備份。取消勾選立即失效快照；可用備份還原，或移除註解標記下新增的綁定。設定檔損壞時不覆寫。

## 驗證

先重跑基線，再測路由狀態、設定升級／衝突／防護條件及序號政策；原生剪貼簿測試保留原內容。用可丟棄 Sublime fixture 實測複製、剪下與貼上，檢查周圍文字及預期剪貼簿。唯讀、多游標、空選取與面板確認不修改；切換目標／移動選取／修飾鍵／並行剪貼簿按取得的實際證據記錄。未驗證的列為未驗證。

依據：[Sublime Key Bindings](https://www.sublimetext.com/docs/key_bindings.html)，官方列出 `read_only`、`selection_empty`、`num_selections`、`panel_has_focus`、`overlay_visible`。
