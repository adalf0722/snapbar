# 多螢幕視窗自由移動設計

日期：2026-11-24

## 目標與已確認方向

設定視窗應遵循 Windows 的一般視窗移動行為。使用者可以將視窗拖到上下、左右排列的其他螢幕，也可以讓視窗跨在兩個螢幕之間或部分超出螢幕。SnapBar 不在移動途中或放開滑鼠後，把視窗強制塞回單一螢幕。

使用者已同意此方向，並明確否決「拖曳結束後依視窗中心所在螢幕校正位置」的方案。

## 問題來源

`src/SnapBar.App/WindowWorkArea.cs` 的 `Attach` 在 `LocationChanged`、`SizeChanged`、載入與 DPI／顯示配置事件呼叫相同的 `Constrain`。此函式依視窗中心選擇螢幕，並呼叫 `SetWindowPos`，將位置與大小限制在該螢幕的工作區。

視窗跨越邊界時，中心尚未到達另一個螢幕，就會被推回原螢幕。只把處理延後到放開滑鼠，仍會推翻使用者刻意跨螢幕擺放的位置。

## 方案取捨

1. **採用：平常自由移動，僅在必要時救援。** 沿用原生拖曳、縮放與貼齊；只在啟動、恢復顯示或顯示配置改變後，檢查是否已無法操作標題列。
2. **不採用：放開後限制在單一工作區。** 仍可能把部分跨屏的視窗拉回，且不允許使用者刻意跨屏擺放。
3. **不採用：限制在虛擬桌面的外接矩形。** 無法反映不同螢幕間的空隙，也會持續干預使用者位置。

## 行為規則

### 一般移動與縮放

- `LocationChanged` 不觸發程式的位置或大小校正。
- 拖曳結束不觸發程式的位置或大小校正。
- 一般 `SizeChanged` 不將視窗縮回某一螢幕的工作區。
- DPI 改變時保留 WPF／Windows 提供的原生位置與尺寸處理，不額外強制置入工作區；可以更新最小尺寸上限，但不得因此改變使用者正在移動的視窗。
- 保留原生最大化、還原、貼齊與鍵盤跨螢幕移動行為。

### 無法操作時的救援

- 檢查時機限於初次顯示、隱藏後重新顯示、由最小化還原，以及顯示配置或工作區變更。
- 使用各螢幕的實際工作區清單判斷，不以虛擬桌面的外接矩形代表可操作區域。
- 以標題列上可拖曳區域是否有至少 96 個邏輯像素寬、標題列高度的連續可見區段為可操作門檻；極小工作區則將門檻縮到可用尺寸。計算時依該視窗 DPI 換算為實體像素。
- 只要任一螢幕提供上述區段，就保留使用者的位置，即使視窗部分超出螢幕、覆蓋工作列或跨屏。
- 必須救援時，選擇距離標題列最近的工作區，只移動到足以恢復上述可拖曳區段；不要求整個視窗可見，也不縮小視窗。
- 如果顯示配置事件在原生移動／縮放期間到達，先記錄待檢查狀態，待操作完成才檢查；沒有配置變更的拖曳結束不檢查。
- 不搶取前景、不變更最大化／最小化狀態；無法取得可靠螢幕資訊時略過救援，不使用固定 1920×1080 邊界猜測位置。

### 小螢幕與共用視窗

- 保留現有設定頁的緊湊版面與捲動行為。初次開啟時可以依目標工作區設定合適的初始尺寸；一般跨螢幕移動不自動縮小。
- 必要時降低最小尺寸，允許使用者手動縮小到目標工作區可用尺寸。
- 修正共用 `WindowWorkArea.Attach`，讓使用相同輔助程式的設定／編輯／結果視窗一致遵循自由移動規則。
- 選字工具列、OCR 選單及其他明確以錨點定位的浮動介面，保留既有的彈出定位策略。
- `SetWorkAreaOverride` 是既有受限版面測試的明確入口；有 override 時保留嚴格限制行為，移除 override 後回到一般自由移動規則。

## 模組分工

- Core：以實體座標表示的幾何判定與最小救援位移，接受視窗／標題列矩形與工作區清單，可注入不同螢幕配置測試。
- Windows：取得實際螢幕工作區、標題列相關尺寸與必要的原生事件資訊；原生讀取失敗時不產生假造配置。
- App：區分一般移動、DPI 更新、必要救援與測試 override；處理原生移動期間的配置變更與生命週期事件，避免重入與無效的延遲工作。

## 驗證與完成條件

- 幾何測試涵蓋上下／左右螢幕、負座標、螢幕空隙、部分跨屏、標題列不可見、最小救援位移與不同 DPI。
- 桌面測試驗證一般移動與放開後不回彈、一般縮放不強制收回、override 保留既有受限版面行為，以及隱藏後重新顯示的救援。
- 檢查拖曳中遇到 DPI／配置事件不會重新套用舊的全視窗限制。
- 執行相關 Core 與 Windows console runner，以及涵蓋設定導覽／共用視窗的桌面套件；不以 `dotnet test` 代替。
- 真實多螢幕／不同縮放比例測試若受目前硬體限制，明確記錄尚未覆蓋的情境，不以模擬測試聲稱已完成真機驗證。
- 新增繁中與英文使用者更新說明，說明可自由跨螢幕移動及僅在無法操作時救援；不更改已發布說明。
- 記錄驗證結果與限制於 `docs/p0-validation.md`。不在本次工作中發布套件或更動選字安全策略。
