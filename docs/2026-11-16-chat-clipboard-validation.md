# 聊天程式相容複製：實作與驗證

## 結果

企業微信已能在 UIA 只提供 Window 的情況下建立相容候選、完成單次 Ctrl+C 讀取並還原剪貼簿。使用者實體測試回覆：企業微信聊天訊息 3/3、企業微信輸入框 3/3、一般微信聊天訊息 3/3。

診斷測試期間取得 29 筆企業微信成功結果，耗時 220.86–253.81 ms；一般相容路徑成功 6 筆，384.28–411.56 ms；原生成功 3 筆，139.78–187.33 ms。這是本機小樣本，未完成或取消的手勢不在成功結果統計中，不代表所有 App／環境的成功率。初期自動化拖曳和手動快捷鍵另有兩筆沒有複製回應，分別 1594.74／1086.27 ms；使用者實體選字後成功，未隱藏或計入成功樣本。

純階段證據與摘要：`artifacts/investigations/chat-routing/selection-trace.jsonl`、`summary.json`。未保存聊天、草稿或剪貼簿文字。

## 實作

- Core 新增企業微信相容資格政策及自動複製退避。已驗證的候選可停止無效的原生 readiness 重試；每次仍先嘗試原生讀取，不以程序層級快取停用 UIA。
- Windows 取得原生 GUI 焦點、滑鼠位置視窗、程序歸屬、視窗類別，以及可用的 MSAA 角色／狀態。不讀取 MSAA 名稱或值。
- 企業微信適配限於 WXWork.exe 的 WeWorkWindow；原生焦點與滑鼠視窗須屬於同一目標程序／根視窗。允許這個自繪視窗缺少細部 MSAA 角色，拒絕已知的非文字角色、停用／隱藏／受保護狀態及原生 password style。
- Probe 為原生來源建立候選 token，與 UIA runtime ID、原生焦點及滑鼠來源綁定。前後驗證重新檢查，不擴充其他 App 的 Window 資格。
- WeCom 根視窗未提供 UIA IsPassword 時，只在上述原生 profile 成立且是目標根 Window 時使用原生／MSAA 路徑；其他未知子欄位仍拒絕。已知密碼旗標仍優先拒絕。企業微信登入／密碼頁未實機驗證，不能宣稱可辨識未公開保護狀態的所有自繪欄位。
- 沿用保存的相容模式偏好。相容結果仍不授權 Cut／Paste；每手勢只送一次 Ctrl+C，不對空內容盲目再送。連續兩次自動相容結果為 no-selection 後暫停該目標的自動複製十秒；原生讀取及手動快捷鍵不受影響，成功可清除退避。

## 同一行重選

使用者回報：從同一行已反白文字內重新拖曳時，像是拖曳原選取，需要先點一下；一般微信沒有相同感受。正常關閉 SnapBar 後，使用者確認企業微信仍會如此。因此本輪未注入額外點擊、Esc 或清除來源選取。這是獨立的企業微信手勢行為，不能把它記成剪貼簿修復失敗或宣稱已修正。
